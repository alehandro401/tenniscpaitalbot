# TennisCapital Bot

Telegram-бот записи в спортивный клуб TennisCapital на **aiogram 3**.
Поддерживает три направления: **теннис** (школы + аренда корта), **бадминтон**
и **пиклбол** (аренда корта + инвентарь).

## Сценарий

0. `/start` → приветствие → выбор вида спорта: **🎾 Теннис / 🏸 Бадминтон / 🏓 Пиклбол**

### Теннис
1. Выбор: **Детская школа / Взрослая школа / Аренда корта**
2. Для школ: **Групповые** (спортивные / любительские / ОФП) или **Персональные**
   (индивидуальные / сплит / семейные)
3. Уровень подготовки: **Начинающий / Опытный** → бот сразу подсказывает
   рекомендованную группу/программу
4. Выбор локации (все 18 клубов из списка)
5. **Если для локации есть подробный прайс-лист** (сейчас — район «Петровка»:
   Театральная / Пушкинская / Трубная) — показывается расписание работы и
   список тарифов с ценами, пользователь выбирает один
6. **Выбор даты** — ближайшие 14 дней
7. **Выбор времени** — только свободные слоты (уже занятые кем-то другим не
   показываются)
8. Формирование ссылки на оплату + кнопка «Я оплатил(а)»
9. После подтверждения — отправка актуальной информации (адрес, дата/время,
   чат группы, контакт администратора)

Для аренды корта (внутри тенниса): категория → локация → длительность
(60/90/120 мин) → дата → время (шаг сетки = выбранной длительности) → оплата.

### Бадминтон и пиклбол

Локация → инвентарь (переключатели: ракетка / воланы или мячи — можно выбрать
несколько или не выбирать вовсе) → контакт/имя/согласие → дата → **время**
(слоты по 1 часу с 06:00 до 24:00; для пиклбола у каждого часа своя цена —
она показана прямо на кнопке) → оплата.

- **Бадминтон** — только Савеловская/Дмитровская, цена флэт 3000 ₽/час.
- **Пиклбол** — Савеловская/Дмитровская/Марьина Роща, цена зависит от времени
  суток и дня недели (будни 06:00–12:00 и 23:00–24:00 — 3500 ₽; 12:00–15:00 —
  3000 ₽; 15:00–23:00 — 4000 ₽; выходные — везде 4000 ₽).

На каждом шаге есть кнопка «◀️ Назад».

### Районы и офферы (теннис)

Для 9 районов заданы точные расписания и прайс-листы (см. `DISTRICTS` в
`data.py`): Петровка, Савеловская, Мичуринская, Минская, Войковская, Шоссе
Энтузиастов, Лужники, Каширская, Южная. В некоторых районах у групповых
занятий несколько разных форматов (обычная группа / мини-группа до 4 человек
/ кардио-группа) — если их больше одного, бот сначала уточняет у клиента
формат, и только потом показывает конкретный прайс-лист.

Для локаций без присланных данных (пока такой список пуст, но на случай
будущего расширения района) используется общее запасное расписание
(`DEFAULT_SCHEDULE` для групп, `PERSONAL_SCHEDULE` для персональных) без
фиксированного прайса.

**Открытый вопрос по данным** (см. комментарий в `data.py` рядом с
`LOCATIONS`): «Ломоносовский проспект» встречается в двух разных районах
(Мичуринская и Минская) — сейчас считается, что это два разных клуба.
Если это ошибка и клуб один — нужно удалить одну из записей в `LOCATIONS`
и в `DISTRICTS`.

### Как устроена сетка времени

- Слоты генерируются с шагом 1 час (для школьных занятий) или с шагом,
  равным выбранной длительности (для аренды корта) — см. `SLOT_STEP_MINUTES`
  и `get_rental_time_slots_for_date()` в `data.py`.
- «Занято» — это любая **не отменённая** заявка (`pending` или `paid`) с той
  же локацией, датой и временем начала. Слот бронируется уже в момент
  формирования ссылки на оплату (`create_order()`), а не после подтверждения
  оплаты — так исключается ситуация, когда два клиента одновременно видят
  один и тот же свободный слот, пока один из них ещё не оплатил.
- Упрощение (MVP): проверка «занято» сравнивает только время начала, без
  учёта фактической длительности занятия/аренды. Например, если кто-то занял
  10:00 на 90 минут, слот 10:30 формально всё ещё покажется свободным. Для
  точного учёта пересечений интервалов потребуется доработать
  `get_booked_times()` — сейчас это сознательно оставлено простым.
- **Изоляция по видам спорта.** У каждой заявки есть поле `Order.sport`
  (`tennis`/`badminton`/`pickleball`). Занятость слота проверяется в пределах
  одного вида спорта — например, бронирование бадминтона на «Савеловская»
  в 19:00 не блокирует теннисный корт на той же станции в то же время, так
  как это разные физические корты.

### Контакт, имя и согласие с документами

После выбора тарифа (или сразу после локации/формата — там, где прайса ещё
нет) бот запрашивает у клиента номер телефона (через нативную функцию
Telegram — кнопку «Отправить контакт», плюс разрешён ручной ввод), затем имя
(текстом — специально не берётся из ника/профиля Telegram, чтобы получить
настоящее имя), затем просит подтвердить согласие с Политикой
конфиденциальности, Правилами школы и Договором оферты (кнопка
«✅ Согласен(на) и продолжить»). Только после этого открывается выбор даты.

Телефон и имя сохраняются и в самой заявке (`Order.contact_phone`,
`Order.contact_name`) — как «снимок» на момент записи, и в профиле клиента
(`Client.phone`, `Client.full_name`) — как последние известные контактные
данные. Согласие фиксируется во времени (`Order.consent_given`,
`Order.consent_at`) для каждой конкретной записи отдельно.

**Ссылки на документы в тексте согласия — заглушки** (`CONSENT_TEXT` в
`data.py`): `https://tenniscapital.ru/privacy`, `/rules`, `/offer`. Замените
на настоящие адреса документов школы перед запуском в продакшен.

### Отмена записи и напоминания

Команда **/cancel** показывает клиенту список его предстоящих записей и
позволяет отменить любую из них — но только если до начала осталось не
меньше **12 часов** (`CANCEL_MIN_HOURS` в `data.py`). Если времени меньше —
бот отказывает и даёт контакт администратора вместо отмены. Отменённая
заявка получает статус `cancelled`, и её слот времени сразу освобождается
для других клиентов (см. `get_booked_times()` в `db.py`).

Фоновая задача в `reminders.py` (запускается из `bot.py` через
`asyncio.create_task`) каждые 5 минут проверяет базу и рассылает напоминания
за **день** и за **час** до начала — только по оплаченным (`status="paid"`)
заявкам. Повторная отправка одного и того же напоминания исключена флагами
`reminder_day_sent` / `reminder_hour_sent` в таблице `orders`.

Ограничение (принято как разумный компромисс для MVP): если бот был выключен
дольше, чем ширина окна проверки (2 часа для напоминания «за день», 30 минут
для «за час»), конкретное напоминание может быть пропущено — оно не
досылается «задним числом».

### Формат телефона

Введённый или переданный через контакт номер приводится к одному из двух
видов функцией `normalize_phone()` в `data.py`:
- 11 цифр, начинается с 7 → `+7XXXXXXXXXX`
- 11 цифр, начинается с 8 → `8XXXXXXXXXX`
- 10 цифр без кода страны → считается российским номером → `+7XXXXXXXXXX`
- всё остальное — считается невалидным, бот просит ввести номер ещё раз.

## Структура проекта

```
bot.py            — точка входа, запуск polling, создание таблиц БД при старте
config.py         — токен бота, ID админов, URL оплаты, строка подключения к БД
states.py         — состояния FSM (шаги диалога, хранятся в памяти процесса)
data.py           — справочники (локации, типы занятий), тексты, генерация ссылки оплаты
keyboards.py      — инлайн-клавиатуры
handlers.py       — вся логика диалога
models.py         — SQLAlchemy-модели: Client, Order
db.py             — подключение к БД и функции работы с клиентами/заявками
reminders.py      — фоновая задача с напоминаниями за день/за час
docker-compose.yml — Postgres для локального запуска
requirements.txt
```

## База данных

Используется PostgreSQL через SQLAlchemy (async) + asyncpg. Две таблицы:

- **clients** — один клиент = одна запись (по `tg_user_id`). Хранит имя,
  username, задел под номер телефона (`phone`, пока не запрашивается ботом,
  но поле уже есть на будущее — например, для сверки со старой базой клиентов
  предприятия).
- **orders** — каждая заявка/запись клиента: направление, тип занятий,
  уровень, локация, статус (`pending` → `paid`), время создания и оплаты.
  Создаётся в момент формирования ссылки на оплату (ещё до подтверждения) —
  это позволяет видеть в базе и тех, кто не завершил оплату.

Таблицы создаются автоматически при первом запуске бота (`init_db()` в
`bot.py`). Если структура таблиц в будущем изменится, а в базе уже будут
данные, лучше перейти на Alembic-миграции вместо автосоздания — так проще
не потерять данные при изменении схемы.

## Запуск

1. Создайте бота через [@BotFather](https://t.me/BotFather) и получите токен.
2. Поднимите Postgres локально (если нет своего сервера):
   ```bash
   docker compose up -d
   ```
3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
4. Задайте переменные окружения:
   ```bash
   export BOT_TOKEN="123456:ABC-your-token"
   export DATABASE_URL="postgresql+asyncpg://bot:bot@localhost:5432/tenniscapital"
   ```
   (или впишите их напрямую в `config.py`)
5. Запустите:
   ```bash
   python bot.py
   ```

## Что нужно доработать перед продакшеном

Это рабочий каркас с точками роста, обозначенными комментариями `ЗАГЛУШКА` в коде:

- **Оплата.** Сейчас `generate_payment_link()` в `data.py` просто собирает
  ссылку вида `https://pay.tenniscapital.ru/pay?order=...` без реального
  списания денег, а подтверждение происходит по нажатию кнопки
  «Я оплатил(а)». Для реального запуска:
  - подключите платёжного провайдера (ЮKassa, Т-Касса/Тинькофф,
    CloudPayments, Robokassa и т.п.) и создавайте реальный платёж в
    `generate_payment_link()`;
  - принимайте подтверждение оплаты через **webhook** от платёжной системы
    (по `order_id`), а не по нажатию кнопки пользователем — иначе кто угодно
    сможет нажать «Я оплатил» без реальной оплаты.
- **Хранилище состояний диалога.** Пока пользователь идёт по шагам мастера
  (ещё не оплатил), его промежуточные ответы хранятся в `MemoryStorage` —
  то есть в оперативной памяти процесса бота, и теряются при перезапуске.
  Для одного процесса это нормально; если бот вырастет до нескольких
  воркеров под нагрузкой, стоит перейти на `RedisStorage` (в aiogram есть
  из коробки, меняется одна строка в `bot.py`, остальной код трогать не надо).
- **Уведомление администратору.** Сейчас после оплаты информация только
  пишется в лог. В `on_payment_confirm()` есть закомментированная заготовка
  для отправки сообщения админам из `ADMIN_IDS` — можно раскомментировать.
- **Экспорт заявок в Excel.** Данные уже лежат в SQL, поэтому выгрузка
  (например, командой `/export` для администратора) добавляется отдельным
  шагом при необходимости — через `pandas.DataFrame` из результатов запроса
  к `orders`/`clients`.
- **Импорт старых клиентов.** Если у школы уже есть база клиентов (Excel/CRM)
  до бота — потребуется разовый скрипт-импортёр в таблицу `clients`, с
  сопоставлением по номеру телефона (поле `phone` уже предусмотрено в схеме).
- **Расписание/цены для остальных локаций.** Подробно заданы только для
  района «Петровка» (см. раздел выше). Как только пришлют аналогичные данные
  по другим локациям — добавляются в `data.py` тем же способом.
- **Учёт длительности при проверке занятости.** Сейчас `get_booked_times()`
  сравнивает только точное время начала, без учёта длительности — см.
  пояснение в разделе «Как устроена сетка времени» выше.
- **Реальные ссылки/контакты.** В `build_final_info_text()` — ссылка на чат
  группы и контакт администратора сейчас плейсхолдеры, замените на реальные.
- **Расписание/тренеры.** Сейчас бот только определяет направление и уровень,
  а не бронирует конкретное время/тренера — это делает администратор вручную
  после оплаты (as per текущее ТЗ). При необходимости легко добавить ещё один
  шаг выбора даты/времени по аналогии с уже реализованными шагами.
