# TennisCapital Bot

Telegram-бот записи в теннисную школу TennisCapital на **aiogram 3**.

## Сценарий

1. `/start` → приветствие → выбор: **Детская школа / Взрослая школа / Аренда корта**
2. Для школ: **Групповые** (спортивные / любительские / ОФП) или **Персональные**
   (индивидуальные / сплит / семейные)
3. Уровень подготовки: **Начинающий / Опытный** → бот сразу подсказывает
   рекомендованную группу/программу
4. Выбор локации (все 14 клубов из списка)
5. Формирование ссылки на оплату + кнопка «Я оплатил(а)»
6. После подтверждения — отправка актуальной информации (адрес, чат группы,
   контакт администратора)

Для аренды корта: категория → локация → длительность (60/90/120 мин) → оплата.

На каждом шаге есть кнопка «◀️ Назад».

## Структура проекта

```
bot.py            — точка входа, запуск polling, создание таблиц БД при старте
config.py         — токен бота, ID админов, URL оплаты, строка подключения к БД
states.py         — состояния FSM (шаги диалога, хранятся в памяти процесса)
data.py           — справочники (локации, типы занятий), тексты, генерация ссылки оплаты
keyboards.py      — инлайн-клавиатуры
handlers.py       — вся логика диалога
models.py         — SQLAlchemy-модели: Client, Order
db.py             — подключение к БД и функции работы с клиентами/заявками
docker-compose.yml — Postgres для локального запуска
requirements.txt
```

## База данных

Используется PostgreSQL через SQLAlchemy (async) + asyncpg. Две таблицы:

- **clients** — один клиент = одна запись (по `tg_user_id`). Хранит имя,
  username, задел под номер телефона (`phone`, пока не запрашивается ботом,
  но поле уже есть на будущее — например, для сверки со старой базой клиентов
  предприятия).
- **orders** — каждая заявка/запись клиента: направление, тип занятий,
  уровень, локация, статус (`pending` → `paid`), время создания и оплаты.
  Создаётся в момент формирования ссылки на оплату (ещё до подтверждения) —
  это позволяет видеть в базе и тех, кто не завершил оплату.

Таблицы создаются автоматически при первом запуске бота (`init_db()` в
`bot.py`). Если структура таблиц в будущем изменится, а в базе уже будут
данные, лучше перейти на Alembic-миграции вместо автосоздания — так проще
не потерять данные при изменении схемы.

## Запуск

1. Создайте бота через [@BotFather](https://t.me/BotFather) и получите токен.
2. Поднимите Postgres локально (если нет своего сервера):
   ```bash
   docker compose up -d
   ```
3. Установите зависимости:
   ```bash
   pip install -r requirements.txt
   ```
4. Задайте переменные окружения:
   ```bash
   export BOT_TOKEN="123456:ABC-your-token"
   export DATABASE_URL="postgresql+asyncpg://bot:bot@localhost:5432/tenniscapital"
   ```
   (или впишите их напрямую в `config.py`)
5. Запустите:
   ```bash
   python bot.py
   ```

## Что нужно доработать перед продакшеном

Это рабочий каркас с точками роста, обозначенными комментариями `ЗАГЛУШКА` в коде:

- **Оплата.** Сейчас `generate_payment_link()` в `data.py` просто собирает
  ссылку вида `https://pay.tenniscapital.ru/pay?order=...` без реального
  списания денег, а подтверждение происходит по нажатию кнопки
  «Я оплатил(а)». Для реального запуска:
  - подключите платёжного провайдера (ЮKassa, Т-Касса/Тинькофф,
    CloudPayments, Robokassa и т.п.) и создавайте реальный платёж в
    `generate_payment_link()`;
  - принимайте подтверждение оплаты через **webhook** от платёжной системы
    (по `order_id`), а не по нажатию кнопки пользователем — иначе кто угодно
    сможет нажать «Я оплатил» без реальной оплаты.
- **Хранилище состояний диалога.** Пока пользователь идёт по шагам мастера
  (ещё не оплатил), его промежуточные ответы хранятся в `MemoryStorage` —
  то есть в оперативной памяти процесса бота, и теряются при перезапуске.
  Для одного процесса это нормально; если бот вырастет до нескольких
  воркеров под нагрузкой, стоит перейти на `RedisStorage` (в aiogram есть
  из коробки, меняется одна строка в `bot.py`, остальной код трогать не надо).
- **Уведомление администратору.** Сейчас после оплаты информация только
  пишется в лог. В `on_payment_confirm()` есть закомментированная заготовка
  для отправки сообщения админам из `ADMIN_IDS` — можно раскомментировать.
- **Экспорт заявок в Excel.** Данные уже лежат в SQL, поэтому выгрузка
  (например, командой `/export` для администратора) добавляется отдельным
  шагом при необходимости — через `pandas.DataFrame` из результатов запроса
  к `orders`/`clients`.
- **Импорт старых клиентов.** Если у школы уже есть база клиентов (Excel/CRM)
  до бота — потребуется разовый скрипт-импортёр в таблицу `clients`, с
  сопоставлением по номеру телефона (поле `phone` уже предусмотрено в схеме).
- **Реальные ссылки/контакты.** В `build_final_info_text()` — ссылка на чат
  группы и контакт администратора сейчас плейсхолдеры, замените на реальные.
- **Расписание/тренеры.** Сейчас бот только определяет направление и уровень,
  а не бронирует конкретное время/тренера — это делает администратор вручную
  после оплаты (as per текущее ТЗ). При необходимости легко добавить ещё один
  шаг выбора даты/времени по аналогии с уже реализованными шагами.
